## 10. lib/worktree-reapability.js — walk-up / shared-root resolution

Confirmed, lines 88-99 (docblock) plus resolveWorktreeRoot() (lines 114-126, called from
collectDirtyStatus at line 175 and countUnpushedCommitsResult at line 227) and realPathOrSelf()
(lines 110-112). Docblock states exactly the three outcomes the SD text references:
```
- git cannot answer at all (no repo anywhere above)  => ownsGitState:false, definitive
- git answers about an ANCESTOR (the walk-up)        => ownsGitState:false, definitive
- git answers about THIS tree                        => ownsGitState:true
```
Mechanism: `git rev-parse --show-toplevel` run with cwd=wtPath; if the directory has no .git of
its own (e.g., removed), git's repo-discovery climbs up to the shared root/ancestor and answers
about THAT tree instead of erroring — resolveWorktreeRoot compares the returned toplevel
(realpath'd, separator/case-tolerant) against wtPath to detect this and reports
ownsGitState:false. realPathOrSelf exists because path.resolve doesn't resolve
junctions/symlinks/8.3 names while git's --show-toplevel does, so a naive string compare would
misclassify a genuinely-owned worktree reached through an alias.
